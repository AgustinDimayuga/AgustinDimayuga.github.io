Hack4Impact Starter Pack

September 8, 2026

This site is the result of working through the Hack4Impact starter pack. The goal was to learn the basics of building and maintaining a personal website while getting more comfortable with HTML, CSS, and Git.

starting from hello world

I started with a single "hello world" page and built everything up in small, committable steps. I began with the basic template files, then added the body of the page, a color scheme, the container layout, and navigation. For the visual style, I went with Dracula, using the purple, pink, and cyan palette you see throughout the site.

One of the biggest things I learned was how useful it can be to work incrementally. Instead of trying to build the entire site and commit everything at once, I made a commit after each small, working change. At first this felt slower, but it made the Git history much more meaningful. I could look back and see exactly when the navigation styling was added, when the project cards were introduced, or when a particular page was changed.

This also made experimenting less intimidating. If I made a change that I didn't like, I had a clear point in the history that I could return to. It helped me start thinking about Git as more than just a place to upload code. It became a way to keep track of how a project develops over time.

putting the pages together

Once the basic styles were in place, I started filling out the rest of the site. I added a portfolio page with cards and tags for projects I've built, a blog, a resume page, and a contact page.

Each page uses the same navigation and container styles. This made it pretty obvious why having a shared stylesheet and consistent markup patterns is useful. When I wanted to change something about the navigation, I could make the change in one place and have it apply across the site instead of maintaining each page separately.

I also started paying more attention to small details that I normally wouldn't think about when just writing HTML. Things like spacing, typography, link states, margins, and how the page behaves at different screen sizes all make a difference in how a site feels.

what I got out of it

Working through the starter pack was a good way to sharpen my fundamentals. I've built multiple web applications using JavaScript as well as frameworks like React, Angular, and Next.js, so I would consider myself at an intermediate level when it comes to building web applications. Because I've spent a lot of time working with frameworks and component-based development, going back to plain HTML and CSS was surprisingly useful.

One thing I had forgotten about was just how much copying and pasting is involved when you aren't using components. With React, Angular, or Next.js, it's natural to create a component once and reuse it wherever you need it. Building this site with plain HTML meant repeating things like the navigation and page structure across multiple files. It made me appreciate how much component-based frameworks help with keeping a project consistent and maintainable.

Writing the CSS myself was also helpful because I normally work with Tailwind CSS in many of my projects. Tailwind makes styling much faster, but some of its utility classes can feel abstract when I don't fully think about what they are doing underneath. Writing the actual CSS for this site made me connect those utilities back to the underlying concepts. Working directly with properties like margin, padding, max-width, display, and flexbox gave me a better understanding of what the Tailwind classes I use are actually changing.

The project also reinforced the value of working in small, deliberate steps. Instead of building everything at once, I made small changes and committed them to Git as I went. This made it easier to see how the site developed and gave me a much clearer history of the decisions I made along the way.

Summary

Overall, I think the starter pack was valuable because it brought me back to the fundamentals that a lot of modern web development builds on. After working with frameworks, components, and higher-level abstractions, it was useful to slow down and build a site with just HTML and CSS. It reminded me that understanding the underlying technologies makes the frameworks and tools I use every day easier to understand as well.

I still want to continue improving the site as I work on more projects, but this gave me a solid foundation for my portfolio and a better appreciation for the basics behind the tools I use to build web applications.
